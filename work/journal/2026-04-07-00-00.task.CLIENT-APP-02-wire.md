## Implementation Log

### Decisions

- **`createClientConfig()` added to `config.ts`** — assembles `ClientConfig` from `PUBLIC_API_PREFIX` and `PUBLIC_DEFAULT_LOCALE` (`$env/static/public`). Keeps the assembly co-located with the type definition, mirroring the server pattern where `src/config.ts` owns config assembly. The call site in `+layout.svelte` stays clean: `setClientApp(createClientApp(createClientConfig()))`.
- **`+layout.svelte` init is client-only** — `setClientApp` is called unconditionally (no `browser` guard needed). During SSR the context is empty; child components calling `getClientApp()` must only do so in client-side contexts (event handlers, `onMount`, etc.). This is expected and documented.
- **`.env` / `.env.example`** — added `PUBLIC_API_PREFIX=/api` and `PUBLIC_DEFAULT_LOCALE=hu`. The old `API_PREFIX` entry in `.env.example` was replaced with the `PUBLIC_`-prefixed variants that SvelteKit's `$env/static/public` requires.
- **`src/routes/client.ts` deleted** — all consumers updated to `getClientApp().services.rpc`.
- **`bun run check`** — 0 errors, 0 warnings.
